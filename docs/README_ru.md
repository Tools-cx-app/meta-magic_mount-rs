# Метамодуль Magic Mount

[![Telegram][telegram-badge]][telegram-url]

</div>

[telegram-badge]: https://img.shields.io/badge/Group-blue?style=for-the-badge&logo=telegram&label=Telegram
[telegram-url]: https://t.me/mmrs_ci

Предоставляет возможности монтирования без использования системных файлов для KernelSU.

Автор будет обновлять этот проект реже из-за студенческих обязательств.

---

## Конфигурация

Путь к файлу конфигурации:

`/data/adb/magic_mount/config.toml`

Пример:

```toml
mountsource = "KSU"
umount = false
partitions = []
extra_mount = []
```

| Field | Описание |
| ------------- | -------------- |
| `mountsource` | Идентификатор источника монтирования, не затрагивающий системный раздел. По умолчанию `"KSU` для соответствия логике KernelSU. |
| `umount` | Попытка размонтирования (зависит от функции umount в KernelSU). |
| `partitions` | Список конкретных разделов, для выполнения операций без использования системного раздела, например, `"mi_ext"`, `"my_stock"`. |
| `tmpfsdir` | Временный путь, по умолчанию `/debug_ramdisk`. Эта опция опциоанальная.|

`extra_mount` по умолчанию равен `[]`. Например, `extra_mount = ["my_product"]` объединяет содержимое `<модуль>/my_product/` с `/my_product/`, а не читает `<модуль>/system/my_product/`. Целевой каталог должен существовать, а `/system/my_product` должен полностью отсутствовать, включая висячие символические ссылки. Указывайте только имена разделов без пути; недопустимые записи пропускаются с сообщением в журнале. Поддерживаются модули без `system/`; маркеры `disable`, `remove` и `skip_mount` сохраняют действие. После изменения конфигурации перезагрузите устройство.

Настройки также можно изменить на странице конфигурации WebUI. MiuiX и MD3 предоставляют редактор «Разделы верхнего уровня модуля» для добавления и удаления имён разделов `extra_mount`. Сохраните настройки и перезагрузите устройство.

## Маркеры каталогов

Создайте пустой файл-маркер в соответствующем каталоге модуля и перезагрузите устройство:

- `.replace`: заменить целевой каталог содержимым модуля, не сохраняя исходное содержимое.
- `.remove`: скрыть целевой каталог целиком. Например, `<модуль>/system/app/Foo/.remove` скрывает `/system/app/Foo`. Флаг действует только для узлов каталогов, не для обычных файлов или символических ссылок. Исходные файлы не удаляются.

`.remove` имеет приоритет над `.replace` в том же каталоге; содержимое этого каталога модуля не монтируется. Сами маркеры не монтируются. Для каталогов `extra_mount` используются те же маркеры. Маркер `remove` (без точки) в корне модуля по-прежнему означает удаление модуля и отличается от `.remove`.


## Пользовательские хуки Lua

Хуки Lua 5.4 заменяют старый текстовый DSL и декларативные правила. **Несовместимое изменение:**
`/data/adb/magic_mount/custom` и `/data/adb/magic_mount/custom.lua` больше не поддерживаются и не читаются.
До перезагрузки вручную преобразуйте старые правила в хуки и перенесите скрипты в `/data/adb/magic_mount/lua/`.
WebUI больше не управляет исключениями и пользовательскими bind-монтированиями и никогда не редактирует скрипты.

Все обычные файлы `.lua` непосредственно в `/data/adb/magic_mount/lua/` загружаются по возрастанию имён
(например, `10-skip.lua`, затем `20-bind.lua`). Подкаталоги не сканируются, символические ссылки не загружаются.
Отсутствие каталога означает отсутствие хуков; ошибки доступа к каталогу, чтения и загрузки скрипта прерывают работу.
Каждый скрипт использует отдельную Lua VM: глобальные переменные не передаются между скриптами.
Любой из хуков можно опустить. Например, создайте `/data/adb/magic_mount/lua/10-custom.lua`:

```lua
function before()
    if modules["example"] then
        modules["example"].skip = true
    end
end

function after()
    bind("/data/local/tmp/source file", "/system/etc/hosts")
end
```

Все `before()` выполняются в порядке имён файлов до сбора модулей и монтирования.
Таблица `modules` индексируется по ID модуля; каждая запись содержит `id`, `name`, `version`, `author`,
`description`, `mode`, `is_mounted`, `enabled`, `source_path`, `rules` (с полями `default_mode` и `paths`)
и изменяемый булев флаг `skip`. Если хотя бы один скрипт задаёт `skip = true`, модуль исключается;
другой скрипт не может включить его значением `false`. Оно также не отменяет маркеры `disable`, `remove`
и `skip_mount`. `moduledir` — корневой каталог модулей (`/data/adb/modules`).
Все `after()` выполняются в порядке имён файлов только после успешного Magic Mount и предоставляют
лишь API монтирования `bind(source, target)`, без `ignore` и API пропуска модулей.
Накопленные bind-монтирования применяются только после успешного завершения всех `after()`.
Ошибки содержат путь скрипта и прерывают текущий этап: ошибки загрузки, синтаксиса или `before`
останавливают работу до монтирования; ошибка `after` отменяет все накопленные bind-монтирования,
но не откатывает уже выполненный Magic Mount. Пути не могут быть пустыми или содержать управляющие символы.
Скрипты считаются доверенной локальной конфигурацией; квот времени и памяти нет.

Команда `modules` и WebUI восстанавливают `is_mounted`, `mode` и `rules` из снимка при запуске по ID модуля.
Модули, пропущенные Lua или добавленные после снимка, отображаются как несмонтированные.
Имя, версия и флаг включения берутся из текущих файлов модуля; их изменение не меняет состояние
монтирования, записанное для текущей загрузки.

Доступны безопасная базовая библиотека Lua и библиотеки table, string, math, utf8; `os`, `io`,
`package`, `debug` и загрузчики файлов недоступны. Цель bind-монтирования должна быть абсолютным
путём без компонентов `..`. Если цель отсутствует, создаётся временная копия дерева от ближайшего
существующего предка, не являющегося корнем. Bind-монтирования остаются доступными только для чтения;
ошибка remount или регистрации отсоединяет монтирование и откатывает операцию.

## Разработка

Зависимости:

* Rust nightly toolchain
* Android NDK
* `cargo-ndk`
* Node.js / npm
* `pnpm` и `vite` как зависимости и фронтенд для webui


Переменные среды:
```shell
export ANDROID_NDK_HOME=<path/to/ndk>
export ANDROID_NDK_ROOT=$ANDROID_NDK_HOME
```

Билд:

```shell
cargo xtask b
```

Файлы билда будут находиться по следующему пути:
* `output/magic_mount_rs.zip`
