# Метамодуль Magic Mount

[![Telegram][telegram-badge]][telegram-url]

</div>

[telegram-badge]: https://img.shields.io/badge/Group-blue?style=for-the-badge&logo=telegram&label=Telegram

Предоставляет возможности монтирования без использования системных файлов для KernelSU.

Автор будет обновлять этот проект реже из-за студенческих обязательств.

---

## Конфигурация

Путь к файлу конфигурации:

`/data/adb/magic_mount/config.toml`

Пример:

```toml
mountsource = "KSU"
umount = false
partitions = []
extra_mount = []
```

| Field | Описание |
| ------------- | -------------- |
| `mountsource` | Идентификатор источника монтирования, не затрагивающий системный раздел. По умолчанию `"KSU` для соответствия логике KernelSU. |
| `umount` | Попытка размонтирования (зависит от функции umount в KernelSU). |
| `partitions` | Список конкретных разделов, для выполнения операций без использования системного раздела, например, `"mi_ext"`, `"my_stock"`. |
| `tmpfsdir` | Временный путь, по умолчанию `/debug_ramdisk`. Эта опция опциоанальная.|

`extra_mount` по умолчанию равен `[]`. Например, `extra_mount = ["my_product"]` объединяет содержимое `<модуль>/my_product/` с `/my_product/`, а не читает `<модуль>/system/my_product/`. Целевой каталог должен существовать, а `/system/my_product` должен полностью отсутствовать, включая висячие символические ссылки. Указывайте только имена разделов без пути; недопустимые записи пропускаются с сообщением в журнале. Поддерживаются модули без `system/`; маркеры `disable`, `remove` и `skip_mount` сохраняют действие. После изменения конфигурации перезагрузите устройство.

Настройки также можно изменить на странице конфигурации WebUI. MiuiX и MD3 предоставляют редактор «Разделы верхнего уровня модуля» для добавления и удаления имён разделов `extra_mount`. Сохраните настройки и перезагрузите устройство.

## Маркеры каталогов

Создайте пустой файл-маркер в соответствующем каталоге модуля и перезагрузите устройство:

- `.replace`: заменить целевой каталог содержимым модуля, не сохраняя исходное содержимое.
- `.remove`: скрыть целевой каталог целиком. Например, `<модуль>/system/app/Foo/.remove` скрывает `/system/app/Foo`. Флаг действует только для узлов каталогов, не для обычных файлов или символических ссылок. Исходные файлы не удаляются.

`.remove` имеет приоритет над `.replace` в том же каталоге; содержимое этого каталога модуля не монтируется. Сами маркеры не монтируются. Для каталогов `extra_mount` используются те же маркеры. Маркер `remove` (без точки) в корне модуля по-прежнему означает удаление модуля и отличается от `.remove`.


## Пользовательские хуки Lua

Разместите скрипты Lua 5.4 в `/data/adb/magic_mount/lua/` и перезагрузите устройство. Загружаются только обычные `.lua` файлы непосредственно в каталоге, по имени; ссылки и подкаталоги исключены. Отсутствие каталога означает отсутствие скриптов. Каждый скрипт имеет отдельную Lua VM.

В начале файла объявите `API = 1` или `API = 2`; API 2 затем требует `MODULE = "ID модуля"`. Каждое объявление литерала занимает отдельную строку; допускаются начальные пробелы, комментарии Lua и оба вида кавычек. API и MODULE доступны только для чтения. Замените `bind` на `bind_mount`, а `modules[id].skip` — на `skip()` API 2. Старые custom/custom.lua не читаются, WebUI не редактирует скрипты.

API 1 предоставляет только функцию монтирования `bind_mount(source, target)` в необязательных `before()/after()`:

~~~lua
API = 1

function before()
    bind_mount("/data/local/tmp/before.conf", "/system/etc/before.conf")
end

function after()
    bind_mount("/data/local/tmp/hosts", "/system/etc/hosts")
end
~~~

Все before накапливают bind по имени файла. После подготовки правил и дерева эти bind выполняются до Magic Mount, который может перекрыть их цели. Все after запускаются только после успешного Magic Mount; bind применяются после успешного завершения всех after. Цели должны быть абсолютными. Пустые пути, управляющие символы и компоненты `..` запрещены. Bind доступны только для чтения; для отсутствующей цели создаётся временное зеркало от ближайшего существующего предка, кроме корня.

API 2 сопоставляет MODULE с ID из module.prop, независимо от имени каталога. Перед сканированием содержимого модуля выполняется поиск ID в `LUAS: FxHashMap` и вызов `load()` без аргументов. Скрипты одного модуля выполняются по имени файла. Для отсутствующих модулей или модулей с disable, remove, skip_mount вызова load нет. Только внутри load API 2 доступны:

- `skip()`: пропустить сканирование содержимого и монтирование всего модуля. Отменяет все его правила, игнорирует следующие правила и останавливает следующие скрипты того же модуля. Без аргументов, повторный вызов допустим; `return` завершает текущий Lua callback. Файл skip_mount не создаётся.
- `block(path)`: исключить только содержимое данного модуля по пути файла или каталога, сохранив системные файлы и содержимое других модулей.
- `replace(source, target)`: источник — обычный файл или каталог по абсолютному пути, цель — относительный путь модуля. Каталог заменяет исходное содержимое целиком. Источник не может быть символической ссылкой или специальным устройством. Последнее объявление для пути имеет приоритет.
- `remove(path)`: скрыть файл, ссылку или каталог в итоговом дереве, включая содержимое других модулей, без удаления с диска. Корни разделов удалять нельзя.

~~~lua
API = 2
MODULE = "example_module"

function load()
    block("system/etc/unwanted.conf")
    replace("/data/local/tmp/hosts", "system/etc/hosts")
    remove("system/app/Example")
end
~~~

Для пропуска всего модуля используйте `skip(); return` в теле load. Относительные пути отсчитываются от корня модуля и включают `system/` или настроенный раздел extra_mount, например `my_product/etc/example.xml`. Абсолютные цели, пустые пути, управляющие символы и `..` запрещены. skip отменяет все правила; иначе приоритет remove > block > replace, родительские block/remove охватывают потомков. Модули без system/ также могут задавать правила. Модули упорядочены по ID, обычный конфликт сохраняет первый источник. block/replace применяются до объединения, remove — к итоговому дереву.

`moduledir` — корень модулей (/data/adb/modules). Доступны базовая библиотека, table/string/math/utf8; os/io/package/debug, загрузчики файлов, rawset и setmetatable недоступны. Ошибки загрузки, before, load и подготовки дерева останавливают работу до монтирования. Ошибка after отменяет bind этапа без отката уже выполненного Magic Mount. Доверенные локальные скрипты не имеют квот времени и памяти.

Команда modules и WebUI читают is_mounted, mode и rules из снимка запуска по ID, не выполняя скрипты. Пропущенные модули остаются в списке как несмонтированные; skip действует только в текущей загрузке. Снимок описывает план, а не успешность каждого монтирования.

## Разработка

Зависимости:

* Rust nightly toolchain
* Android NDK
* `cargo-ndk`
* Node.js / npm
* `pnpm` и `vite` как зависимости и фронтенд для webui


Переменные среды:
```shell
export ANDROID_NDK_HOME=<path/to/ndk>
export ANDROID_NDK_ROOT=$ANDROID_NDK_HOME
```

Билд:

```shell
cargo xtask b
```

Файлы билда будут находиться по следующему пути:
* `output/magic_mount_rs.zip`
